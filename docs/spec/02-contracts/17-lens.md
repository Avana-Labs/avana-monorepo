# 2.17 Lens

> **Status:** In review · **Owner:** Avana Labs · **Last reviewed:** 2026-11-12
>
> **Requirement prefix:** `REQ-LENS-NNN`

## Purpose

An immutable, read-only periphery contract, one per chain, that gathers protocol state into single-call views for the app, the keeper, monitoring and the public backing proof. It sits outside the audited core: no core contract calls it, stores its address or depends on anything it returns, and nothing it returns authorizes an action (`Q-319`). It reports: the account of one wallet in one market (its PositionProxy on that market's CDP Spoke, with the market's collateral and every debt reserve), the backing check (including any pending settlement of a reconciled seizure, as n-token amounts), collateral and debt price states with the served price next to the last accepted one, the pause state and reason of each Hub, circuit-breaker status, address freezes, cap headroom keyed by Hub and market, the tail coverage of each (Hub, debt asset) First-Loss Reserve held in its Avana Umbrella (First-Loss Reserve), Avana's protocol safety module (`Q-402`), and previews built to succeed when they land in a later block: a liquidation preview that returns ready-to-send `LiquidationParams` (`Q-232`, `Q-268`), the recommended borrow at health factor 1.10 next to the protocol maximum at 1.00 (`Q-398`), the repay-all spend cap, a re-credit and a repay with collateral. For the app's pages it also reports a position's uncollected fees, the health factor and liquidation price after a borrow, repay, pledge or withdrawal, the largest removal and the smallest repay with collateral for a target health factor, everything an account repays and withdraws to close, each Hub asset with its allocation by Spoke, and each market's risk configuration. Positions are named by `(integrationId, positionKey)`, the AMM integration's key for a position (for an NFT position, `bytes32(tokenId)` on Uniswap v3 and `bytes32((uint256(generation) << 248) | tokenId)` on Aerodrome Slipstream, the generation naming the market's position manager and factory pair, [2.19](19-amm-integration-interface.md) `SPEC-AMM-CORE-002`), never by an NFT ID alone; every token amount is an array in the market's pool-token order. Every value it returns is read from the deployed Avana and Aave contracts in the same call. Every account-level function takes the market (and so its CDP Spoke and Hub) as an argument, so one Lens serves every Hub, CDP Spoke, AMM protocol and market on its chain.

The Lens is **not** part of the protocol's security. Its liquidation preview sizes `debtToCover` with the pinned Aave V4 liquidation formulas so that a caller without keeper tooling can submit a correct call, but LPVaultSwap recomputes and enforces every check on execution, Aave sizes the seizure inside `liquidationCall`, and settlement uses balance deltas, never a preview. Each preview carries the margin that keeps the transaction made from it valid between the block it was read at and the block that includes it (interest accrual, a one-wei repay near Aave's dust threshold), so a margin can only make the preview more conservative than execution, never less (`Q-268`). A Lens bug can mislead a user or keeper into a transaction that reverts or pays less than shown; it cannot move value, so the Lens is reviewed and tested as periphery, not audited with the core.

Return structs only (and the `PauseState` enum of `getApplicationState`). Every returned struct carries `blockNumber` and `timestamp` of the block it was read at. No state changes, no events, no token movements.

## Restrictions

### Form and role

- `REQ-LENS-001` The Lens MUST be immutable: no proxy, no state-changing function, no storage other than constructor immutables and compile-time constants, no owner, no admin and no role; every external function is `view`. Being stateless, it can be replaced at any time without migrating anything. The Lens is one entry point and nine immutable modules, each serving one or more interface pieces or parts of them, as the Storage table lists (`LensAccountModule`, `LensMarketModule`, `LensPriceModule`, `LensLiquidationModule`, `LensRiskModule`, `LensPreviewModule`, `LensMarketsModule`, `LensPositionsModule`, `LensSpeedModule`): the entry point forwards each call by STATICCALL with the caller's calldata unchanged to the module that serves it and returns the module's return or revert data unchanged, and the constructor reverts `InvalidModules()` unless the nine modules report the same nine core addresses (and the liquidation module's `AAVE_SIZING` is non-zero). Each module is itself immutable and read-only and checks the Lock, so a call made to a module directly answers exactly as the same call through the entry point. Why: the views together compile to well over 150 KB, more than six times EIP-170's 24,576-byte limit; spreading the pieces over nine modules keeps each deployed contract within the limit and its 1,024-byte margin, and a STATICCALL can neither change state nor be redirected by any caller input. (Source: Q-119, Q-226)
- `REQ-LENS-002` A new Lens is a new deployment: one is deployed when a dependency's interface changes or a new Avana contract version needs new reads, and the verified deployment manifest bundled in `packages/protocol` records the address consumers use. Replacing the Lens requires no governance action and changes no protocol state; the previous Lens keeps answering until its reads fail. ABIs are generated from the release-commit build into `packages/protocol`, and the ABI hash in the manifest is checked at startup by the app, the indexer and the keeper. (Source: Q-119, Q-226)
- `REQ-LENS-003` No Avana core contract (AaveAdapter, ProxyManager, PositionProxies, Collateralization, every LPVault and AMM integration, vault tokens, Lock, RiskModule, MarketRegistry, ParameterStore, LPOracle, DebtOracle, LPVaultSwap, swap routes, the IFlashSource implementation, PayoutEscrow, AvanaTimelock) MAY store the Lens address or call it, and no Aave payload or keeper contract MAY use a Lens result on-chain as a condition. The Lens is periphery outside the audited core: its code is reviewed and tested with the conformance suite, and a Lens defect is a display or preview defect, never a custody or accounting one. The liquidation sizing in `previewLiquidation` (`REQ-LENS-017`) is the pinned Aave V4 formula compiled into the Lens for previews only; on execution Aave sizes the seizure inside `liquidationCall`, and LPVaultSwap measures what was spent and seized by balance delta. (Source: Q-060, Q-116, Q-119, Q-232, Q-319)
- `REQ-LENS-004` Lens results are advisory. The keeper and the app MUST re-read the authoritative values by RPC at a fixed block before acting, and every Avana contract re-checks its own conditions on execution: LPVaultSwap recomputes every liquidation gate, the flash-premium bound, the per-leg minimum outputs and the recovery floor, so a stale or wrong preview can only make a call revert or pay its caller less, never move value it should not. Indexed data (debt shares, index snapshots) is historical only; every displayed health factor, keeper decision and preparation re-reads the chain, and the keeper enumerates proxies from on-chain `ProxyDeployed` (ProxyManager) and `UserProxyCreated` (AaveAdapter) logs through two independent RPC sources. (Source: Q-119, Q-232)

### Price state

- `REQ-LENS-015` `getPriceState(vaultToken)` MUST return, from the market's LPOracle feed (`getPriceState()`, computed by the same code as `latestAnswer()` in the same block) in the same call, with the chain's sequencer and second-source gates in `borrowAllowed` (the LPOracle's own flag, which is false while the sequencer is down or in its grace period, and always reflects an up sequencer on Ethereum): state (Live, Drifting, Cached, Expired) and reasons, the served price `price` (8 decimals) from `latestAnswer()`, the last accepted price and its time `acceptedPrice`, `acceptedAt` from `lastAcceptedPrice()`, each Chainlink input's feed address (one `PriceInput` per leg of the route each token is served from, in pool order), original source timestamp and age (`timestamp − updatedAt`, 0 for a timestamp in the future), the primary-vs-alternate deviation, the disagreement fields (`disagreeSince`, `disagreementPauseActive`, and `disagreementExpired = (some token disagrees ∧ timestamp ≥ disagreeStart + disagreementPauseMax)`, where `disagreeStart` is the LPOracle's stored first observation or `timestamp` if none), `liquidationState` (the state LPVaultSwap applies when this market is the one seized: the price state, with a disagreement past `disagreementPauseMax` reported as Expired, a serving alternate leg older than its `borrowPriceMaxAge` (LPOracle reason bit 12) as Cached, and a Live market inside a disagreement pause as Drifting), and the grace latch (`recoveredAt`, `recoveredAt + graceDuration`, `graceHealthFactor`). For each input it MUST also report `borrowFresh = updatedAt ≤ timestamp ∧ age ≤ borrowPriceMaxAge(feed)` (the RiskModule's rule, which refuses a timestamp in the future) and `liquidationFresh = age ≤ liquidationPriceMaxAge(feed)` (LPVaultSwap's rule, which counts it age 0), using the values read from the ParameterStore in the same call; both bounds are inclusive. The view is computed by the same code as `latestAnswer()` in the same block. The served price is what Aave uses for every account holding the market: the accepted price while Live, Drifting or Cached, the LP price built from the lower of each token's two route answers during a disagreement, and `1` (10⁻⁸ USD per whole vault token, collateral counted as worthless) while Expired (`REQ-ORACLE-085`, `REQ-ORACLE-086`, `SPEC-ORC-017`); `price ≤ acceptedPrice` whenever the state is not Live. Avana's own valuations in the Lens (caps, minimum pledge value, re-credit charge) use `acceptedPrice`. Why: the served price decides liquidation eligibility of every other reserve of the account (`Q-247`), while the accepted price is what the market is worth once it recovers; showing both tells the borrower how far a failing market has pushed the health factor down and that repaying or adding collateral in a fresh market restores it. **Example:** routes for token1 have disagreed since `disagreeSince = 1,762,696,000`, `disagreementPauseMax = 3,600` s, the accepted price is 1.99980000 and token1's routes answer 1.0000 and 0.9750; at `timestamp = 1,762,698,000` the pause is active (`disagreementPauseActive = true`, `liquidationState = Drifting`, this market cannot be seized), `price = 197,483,855` (1.97483855: `price8` of `SPEC-ORC-008` at the lower route, for a full-range USDC/USDT market with `d = 6`, as in `SPEC-ORC-017`) and `acceptedPrice = 199,980,000`, and the account's other fresh markets stay liquidable with this market counted at 1.97483855; at `1,762,699,600` the bound has passed and `liquidationState = Expired`; if the market's own state reaches Expired, `price = 1` and `acceptedPrice` stays 199,980,000. Repay and debt-free withdrawal stay open throughout. (Source: Q-119, Q-128, Q-154, Q-162, Q-182, Q-196, Q-199, Q-208, Q-247, Q-274)
- `REQ-LENS-030` `getDebtPriceState(spoke, debtReserveId)` MUST return, for an approved debt reserve of `spoke` (`MarketRegistry.isApprovedDebtReserve`, else `UnknownDebtReserve(spoke, debtReserveId)`): `source = AaveOracle.getReserveSource(debtReserveId)` read through the Spoke's `ORACLE`, the served `price = getReservePrice(debtReserveId)` (USD, 8 decimals), `fixedPrice` from the reserve's `DebtReserveDef`, and for a DebtOracle source (every debt reserve Aave does not price at a fixed $1.00, `Q-248`) its `state` and `updatedAt = servedUpdatedAt` (the source timestamp of the route whose value is served, read live; the accepted price's stored timestamp moves only on a poke, which execution does first) from `getPriceState()`, `acceptedPrice` from `lastAcceptedPrice()`, `age = timestamp − updatedAt` (0 for a timestamp in the future), and the flags by execution's own rules: `borrowFresh = state is Live ∧ borrowAllowed ∧ updatedAt ≤ timestamp ∧ age ≤ borrowPriceMaxAge()` of the DebtOracle, the RiskModule's debt-price step ([2.7](07-risk-module.md) `REQ-RISK-061`), and `liquidationFresh = state is Live ∧ ¬liquidationPaused ∧` each used leg of the served route within `liquidationPriceMaxAge(feed)` of the ParameterStore (a leg timestamp in the future counting age 0), LPVaultSwap's debt-price rule ([2.11](11-lpvaultswap.md) `REQ-SWAP-091`), both bounds inclusive, with `borrowAllowed` and `liquidationPaused` the DebtOracle's own flags from the same `getPriceState()` (the RiskModule refuses a borrow while `borrowAllowed` is false, and LPVaultSwap refuses to repay the reserve while `liquidationPaused` is true: while the sequencer is down, or while a serving alternate's leg is past its `borrowPriceMaxAge`, the state can be Live with a fresh accepted price and still be closed to both), (a route that names no feed is never fresh), with the values read in the same call, and `stressPriced = price > acceptedPrice`. For a fixed $1.00 source such as GHO's (`Q-100`, `Q-238`) it returns `fixedPrice = true`, `state = Live`, `acceptedPrice = price`, `updatedAt = timestamp`, `age = 0`, both flags `true` and `stressPriced = false`, because a fixed price never goes stale. A source that differs from the one the MarketRegistry recorded is reported as found; the RiskModule and LPVaultSwap reject it on execution. The served price is the accepted price while Live or Cached, the higher of the two route answers during a disagreement, and `⌈acceptedPrice × (10⁴ + debtStressRiseBps) / 10⁴⌉` once Expired (`SPEC-ORC-018`), so `price ≥ acceptedPrice` whenever the state is not Live. Why: a debt price that is not fresh blocks the account's borrowing and withdraw-with-debt, and blocks liquidation that repays this reserve, while liquidation that repays another fresh reserve still runs with this debt counted at its served price (`Q-247`); the app and keepers need that freshness and the stress valuation next to the collateral price states. **Example:** the USDC reserve 2 is priced by its DebtOracle, whose primary leg has a 3,600 s heartbeat, so `borrowPriceMaxAge = liquidationPriceMaxAge = 4,200` s (`Q-274`); the accepted round is 0.99990000 at `updatedAt = 1,762,696,000`. At `timestamp = 1,762,697,800`, `state = Live`, `age = 1,800`, both flags `true`, `price = 99,990,000`. If both routes then stall, at `1,762,700,500` the state is Cached, `price = acceptedPrice = 99,990,000`, both flags `false`: no account borrows USDC and no liquidation repays reserve 2, while liquidation repaying the account's GHO debt still runs. Once Expired with `debtStressRiseBps = 500`, `price = ⌈99,990,000 × 10,500 / 10⁴⌉ = 104,989,500` (1.049895) and `stressPriced = true`. (Source: Q-100, Q-182, Q-234, Q-238, Q-247, Q-248, Q-274)
- `REQ-LENS-031` `getApplicationState(hub)` MUST return `MARKET_REGISTRY.pauseState(hub)` (`None`, `Frozen` or `Paused`) and `getPauseReason(hub)` MUST return `MARKET_REGISTRY.pauseReason(hub)` as its `PauseReason` ordinal (0 None, 1 General, 2 MintPathSuspect), both of the same block. A withdrawal takes `amount = previewRelease` of the record when the position is an open record of the wallet's proxy and 0 otherwise, the collateral after is `max(0, assets − amount)`, and `CF'` is the reserve's latest when `amount > 0` and the collateral flag is on (the withdrawal refreshes the account), the account's own otherwise. Units and assets move one for one while the Hub asset's added shares equal its added assets (`REQ-LENS-012`). **Example:** with 9,000 GHO owed on 10,000 vault tokens at $2.00 (HF 1.7778), pledging a 5,000-unit position gives `healthFactorAfter = 2.6667` (`30,000 × 0.8 / 9,000`); with 7,000 GHO owed on records of 10,000 and 6,000, withdrawing the 6,000 record gives 2.2857 (`20,000 × 0.8 / 7,000`). Checked by: TEST-247. (Source: Q-119)

### Inverse sizing

- `REQ-LENS-054` `previewMaxWithdraw(wallet, marketId, targetHealthFactor)` MUST return a `RemovalSizing` with each record of the account in seizure-list order and its `units` (`previewRelease`, what `AaveAdapter.withdraw` takes), `target`, `maxUnits`, each record's `fits = units > 0 ∧ units ≤ maxUnits`, and `bestIndex`, the record with the most units among those that fit (`type(uint256).max` when none does). With no debt, `target = targetHealthFactor` and `maxUnits` is every record's units: a debt-free withdrawal is open in every state. With debt, `target = max(targetHealthFactor, 1e18, hardHealthFloor(marketId))`, and `maxUnits` is 0 unless the account's gate status reports `withdrawWithDebtAllowed`, the Hub is not `Paused` and the wallet is not frozen; otherwise, with `CF` the reserve's latest collateral factor (to which the withdrawal moves the account), `per = Pc × 10^(18 − d) × CF` at the served price, `W = ⌊assets × per / 10⁴⌋`, the rescue exclusion `E` of `SPEC-CF-005` at `CF` and `need = ⌈target × totalDebtValueRay / (WAD × RAY)⌉`: `maxUnits = min(assets, ⌊(W − E − need) × 10⁴ / per⌋)`, and 0 when `W < E + need` or nothing is counted. This is the largest `u` with `W − E − ⌈u × per / 10⁴⌉ ≥ need`, and that inequality holds exactly when the rescue-excluded health factor after removing `u` is at least `target`, so the bound is exact for the check it states; it subtracts `E` in full even when a withdrawn record carries rescue units, and Aave, which rounds once, accepts at least as much. Withdrawals are whole records, so `fits` tells the app which record it can withdraw alone. **Example:** records of 10,000 and 6,000 vault tokens at $2.00, CF 80 %, 10,000 GHO owed, target 1.25: `W = $25,600`, `need = $12,500`, `maxUnits = 8,187,500,000` (8,187.5 vault tokens, after which Aave's health factor is exactly 1.25), the 6,000 record fits and the 10,000 one does not, `bestIndex = 1`; withdrawing the 6,000 record leaves HF 1.60. Checked by: TEST-247, MATH-AR-76. (Source: Q-119, Q-253, Q-398)
- `REQ-LENS-055` `previewDeleverageTo(wallet, marketId, positionKey, debtReserveId, targetHealthFactor)` MUST return a `DeleverageSizing` for one record and one enabled debt reserve (`UnknownDebtReserve` otherwise), with `T = max(targetHealthFactor, 1e18)`: `reachable = false` and every amount 0 when a repay with collateral of the record is closed (the gates of `REQ-LENS-038`; the most units it can use is the record's `previewRelease`); `reachable = true`, `units = 0` and `healthFactorAfter` the current health factor when that is already at least `T`; otherwise, with `x(u)` and `HF(u)` the repayment and health factor after of `REQ-LENS-038` for `u` units (read once, evaluated as pure arithmetic), `uFull` the fewest units in `[1, limit]` with `x(u)` equal to the reserve's debt (`limit` when none), `reachable = false` when `HF(uFull) < T`, and otherwise the result of bisecting `[0, uFull]` with the upper end always reaching `T` (`x > 0` and `HF ≥ T`) and the lower end not: `units` reaches `T` and `units − 1` does not, with `debtRepaid = x(units)`, `healthFactorAfter = HF(units)` and `debtAssetToWallet` as `REQ-LENS-038` returns them for `units`. Repaying with more units after the reserve's debt is cleared only removes collateral, so `uFull` bounds the search. The bisection returns only a value it has evaluated as reaching `T`, so the units shown always reach the target. Bounded by two bisections of at most 128 steps. **Example:** Alice owes 12,000 GHO on 10,000 vault tokens at $2.00 (HF 1.3333) and targets 1.60: the view returns about 2,046 vault tokens repaying about 4,046 GHO, and one unit fewer leaves the health factor below 1.60; with 2,000 GHO owed and the largest target, `units` is the fewest that repay the whole 2,000 GHO and `healthFactorAfter = type(uint256).max`. Checked by: TEST-247. (Source: Q-254, Q-255, Q-268)
- `REQ-LENS-056` `previewCloseAccount(wallet, marketId, deadline)` MUST return a `CloseAccountView` with one `DebtClose` per enabled debt reserve the account owes on, in `getDebtReserveIds` order (`reserveId`, `asset`, `total = getUserTotalDebt` and `maxRepaySpend`, the `quoteRepayAll` of `REQ-LENS-036` for `deadline`), and one `RecordClose` per record in seizure-list order (`positionKey`, `units = previewRelease`, and `amounts = composition(marketId, units, prices)` of the market's AMM integration at the LPOracle's token prices, one zero per pool token when a token price is 0 or `units` is 0); both lists are empty before the proxy is deployed. Repay is open in every state and, once nothing is owed, every withdrawal is debt-free and open in every state, so an account can always close with `debts.length` repay-all calls and `records.length` withdrawals. **Example:** Alice with 5,000 GHO and 1,000 USDC owed and records of 10,000 and 3,000 vault tokens gets two debts with their repay-all quotes and two records with 10,000,000,000 and 3,000,000,000 units. Checked by: TEST-247. (Source: Q-119, Q-269)

### Market risk configuration and Hub assets

- `REQ-LENS-057` The `MarketView` of `REQ-LENS-045` MUST also carry the market's risk configuration: `collateralRiskBps` (the vault-token reserve's `collateralRisk`), `liquidationFeeBps` (its latest dynamic configuration), the Spoke's `targetHealthFactor`, `healthFactorForMaxBonus` and `liquidationBonusFactorBps` (`getLiquidationConfig`), `hardHealthFloor(marketId)`, Avana's caps (`marketUsdCap`, `topUpSliceUsd`, the market's Hub's `depositorUsdCap` and one `tokenUsdCap(hub, token)` per pool token, USD 8 decimals), the Hub's `addCap` of the vault token on the Spoke (whole units, `type(uint40).max` meaning none), and for each enabled debt reserve of the Spoke (`debtReserveIds`) the rate the market's borrowers pay, `borrowRatesRay = ⌈drawnRate × (10⁴ + collateralRiskBps) / 10⁴⌉`. An account holds one collateral reserve, and Aave V4's risk premium over one collateral is that reserve's `collateralRisk`, so this is the rate of every account of the market (`REQ-LENS-047`). **Example:** a drawn rate of 6 % and `collateralRisk = 500` bps give 6.30 % for every borrower of the market. Checked by: TEST-247. (Source: Q-119, Q-307)
- `REQ-LENS-058` `getHubAsset(hub, assetId)` MUST return, for an asset the Hub lists (`getAssetUnderlyingAndDecimals` names a non-zero underlying, else `UnknownHubAsset(hub, assetId)`), a `HubAssetView` with `underlying`, `decimals`, `added` and `addedShares`, `drawn` and `premium` (`getAssetOwed`), `owed = getAssetTotalOwed`, `drawnShares` and `premiumShares`, `liquidity = getAssetLiquidity`, `swept`, `deficit = ⌈getAssetDeficitRay / RAY⌉`, `accruedFees = getAssetAccruedFees`, `utilizationBps` and `supplyRateRay` as `REQ-LENS-046` (rounded down), `drawnRateRay`, `liquidityFeeBps`, `feeReceiver`, `irStrategy` and the rate curve, `lendSpoke` (the first Spoke of kind `Lend` in the Hub's order, `REQ-LENS-059`, 0 when none) with `priceUsd8`, its AaveOracle's price of the asset (`getReservePrice(getReserveId(hub, assetId))`, 0 without a Lend Spoke), and one slice per Spoke (`REQ-LENS-059`). The available liquidity is `liquidity`, the bound of every draw and every lender's withdrawal, not `added − owed`: the Hub holds `added + accruedFees = liquidity + swept + owed + deficit`. Checked by: TEST-247. (Source: Q-119, Q-353)
- `REQ-LENS-059` Each `SpokeDraw` of `getHubAsset` and `getHubAssetExposure` MUST carry, for one Spoke registered on the Hub asset: `spoke`, `homeHub = MarketRegistry.hubOf(spoke)`, `drawCap` and `addCap` (whole units), `active` and `halted` (`getSpokeConfig`), `drawn = getSpokeTotalOwed` with its split `drawnOwed` and `premiumOwed` (`getSpokeOwed`), `deficit = ⌈getSpokeDeficitRay / RAY⌉`, `added = getSpokeAddedAssets`, `addedShares`, `drawnShares` and `premiumShares`, and `kind`: `Cdp` when `homeHub ≠ 0`, else `Coverage` when the Spoke is `firstLossReserveOf(hub, underlying)`, else `FeeReceiver` when it is the asset's `feeReceiver`, else `DeficitOffset` when its `FIRST_LOSS_LAYER()` returns `firstLossReserveOf(hub, underlying)` (the match rule of `REQ-LENS-042`: the pair's DAO deficit offset, 2.14 `REQ-FLR-046`), else `Lend` on a lend asset (`REQ-HUB-015` admits no other Spoke there) and `Other` on a market's vault-token asset (`marketOfHubAsset(hub, assetId) ≠ 0`), where only the CDP Spoke and the fee receiver belong.
