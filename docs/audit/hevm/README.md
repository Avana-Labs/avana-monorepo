# hevm

## What it proves

`hevm symbolic` proves each assertion entry point of every `*Properties` harness (QED: no reachable assertion violation; a partial exploration fails), checks the runtime code of every `src/` contract and library for assertion violations, and runs `hevm test` on any `prove_` function in `test/symbolic/`.

## The state hevm runs in

Every target runs against a local anvil chain (`hevm symbolic --rpc`), so it starts from a state a deployment can have:

- **Harness entry points.** The harness is deployed on the chain first. Its constructor deploys and configures the contracts it tests, as it does for Echidna and Medusa, and each entry point is then explored from that state; every contract the call reaches executes from its deployed code and storage.
- **`src/` runtime code.** The contract's runtime code is placed on the chain with each address immutable filled with an address of its own, as a constructor fills it, and each own-address immutable (`_SELF`, `__self`, `_cachedThis`) set to the contract's address. Every filled address, and address 0 (an address read from the empty storage), holds the code `PUSH0 PUSH0 REVERT`, so a call to it reverts with empty data, which the caller passes on or handles; an address the caller passes resolves only to accounts on the chain (`--only-deployed`), so a caller-chosen contract cannot hand back free revert data either. A `Panic(1)` can then only come from an `assert` in the contract's own code. Paths that continue after a successful call to another contract are explored by the harness targets, where that contract is deployed.
- **Block context.** hevm 0.58 reads the block number, coinbase, base fee and prevrandao of the block it fetches, but leaves `block.timestamp` symbolic unless `--timestamp` is given, and uses chain id 1 unless `--chainid` is given. A symbolic timestamp includes times before the deployed state was written and times at or above 2^64. In run 43387180884 (`c07ddca`), `SpeedLimitMathProperties.charge(0)` could only fail through such a timestamp (`SpeedLimitMath.roll` casts it to `uint64`), and every counterexample of that run returned normally when replayed with `cast call` on the deployed harness. Each run therefore takes the timestamp, number and chain id of the chain block it reads the state from.
- **Solvers and memory.** One z3 instance per run (`--num-solvers 1`) with `HEVM_SMT_MEMORY` megabytes (10,240 in CI). At hevm's default of one instance per CPU with 1,024 MB each, z3 answered `(error "out of memory")` on the RiskModule, SettlementMath and LPPriceMath harnesses in that run. In CI, hevm and z3 also run in a systemd scope capped at `SECURITY_MEMORY_MAX` (14 GB), so a run that needs more ends with "OUT OF MEMORY" in its log instead of the runner shutting down, as it did on `PositionProxyProperties`.
- **Iteration bound.** `ParameterStoreListingProperties.setFeed` and `setFeed9` … `setFeed13` run with `--max-iterations 32` (`HEVM_MAX_ITERATIONS_FOR`). The branch hevm stopped at (pc `0x3e5c`, `0x3fa6` in the current build, of `ParameterStoreListingLogic`) is the address check of its ABI decoder, which a successful `setFeed` on the deployed harness passes 22 times in one call frame (counted with `debug_traceCall` on anvil); the default bound of 5 cut those paths. At 32 the six entry points are fully explored and end with counterexamples that are spurious (see "Spurious counterexamples of setFeed").

Why: on bare runtime code the immutables are zero, the storage is empty and every contract called is unknown code whose revert data hevm leaves free. Every call whose failure the contract passes on (a bubbled revert) then became an "assertion violation" with `Panic(1)` as that free data. The run on `main` of 2026-11-12 (commit `a6d7acd`) reported such counterexamples on 41 targets, for example 18 on `Collateralization`, one per function that first calls the Lock (`nextRecordId()` included: `ILock(_LOCK).holder()` with `_LOCK = 0`); `ParameterStoreProperties` delegatecalls its logic contracts through immutables that were zero. None was an assertion of Avana's code: the only `assert` in `src/` is `CollateralizationLedger` line 94 (`pos < len` in the seizure list), which `CollateralizationProperties` and the Collateralization ledger invariants exercise. The other failed harness targets were partial explorations (z3 out of memory, symbolic exponents in `LPPriceMath`, the iteration bound), which still fail the run.

## Spurious counterexamples of setFeed

`ParameterStoreListingProperties.setFeed` (decimals outside 9–18) and `setFeed9` … `setFeed13` end at `--max-iterations 32` with counterexamples to `ok == (normalised && hi > lo)`. None is a reachable assertion violation:

- **Replay.** Every counterexample returns normally when replayed with `cast call` on the deployed harness: 11 of 11 from run 43595414156 (`aa340fb`, replayed on anvil with the creation code of that run, 2026-11-14), and 0 of 13 reproduced by the runner's own replay in run 43653574421 (`48864ef`). The runner reports such entry points as "unconfirmed", which does not fail the step; that job passed.
- **The models contradict the code.** hevm reports the delegatecall into `ParameterStoreListingLogic.setFeed` as succeeding for inputs that `_pin` rejects for every reason it has (decimals 0, 20, 21, 64 and 138; a minimum of 0 or below 0; a maximum below the minimum, `setFeed(8, 524288, 8)`; a minimum below `10^(decimals − 8)`, `setFeed9(1, 1049218)`, `setFeed14(2, 1000003)`), and as failing for valid inputs (`setFeed9(254, 256)`, `setFeed(3, 64, 475713)`). On the deployed harness the call succeeds exactly when `_pin` accepts: `setFeed`'s fixed heartbeat, margin, deviation and ages pass its bounds; `_recheck(SCOPE_FEED, feed, true)` and `_recheckMargins` find no market token whose routes or second sources use the pinned feed (the harness registry's tokens have no routes, USDT's second source is a pool TWAP), so neither calls an LPOracle nor reverts; `_pin` succeeds exactly for `1 ≤ decimals ≤ 18`, `minAnswer > 0`, `minAnswer ≥ 10^(decimals − 8)` above 8 decimals and `maxAnswer > minAnswer`, the harness predicate.
- **hevm settings.** Locally (hevm 0.58.0, the same chain set-up), `setFeed9` gives such counterexamples with path merging off (`--merge-max-budget 0`), with `--no-simplify`, `--no-decompose` and the Naive loop heuristic; `setFeed14`, QED at the default bound, gives one (`setFeed14(2, 1000003)`) at `--max-iterations 32`. At the default bound `setFeed9` is explored partially and still prints a counterexample (`setFeed9(254, 256)`).

The counterexamples are therefore an hevm artefact, not a gap in the harness or the code. They appear once the frame revisits the decoder check more often than the default bound allows; which part of hevm loses the constraint on the call's result was not traced. Bounds of 5 and 32 were tried; an unbounded run (`--max-iterations -1`) has not been run yet. The harness cannot remove all the decoder passes: they decode the registry's `getMarket` and `getToken` answers in `_recheck` and `_recheckMargins`.

## How to run

From `contracts/`, hevm 0.58.0 with z3:

```bash
script/security-slow.sh build hevm
HEVM_SMT_TIMEOUT=600 script/security-slow.sh build hevm       # nightly budget
```

`HEVM_SMT_TIMEOUT` is 300 s per query by default.

## Scope

Harness entry points of AvanaRoles, Lock and LockSlot; runtime code of AmmConstants, AvanaRoles, BreakerReasons, LensConstants, Lock, LockSlot, RiskModuleConstants. `test/symbolic/` holds no `prove_` function yet.

## How often it runs

Slow tier at each layer gate and on every push to `main` in CI (`security-slow.yml`), one job per target: each harness's assertion entry points and each `src/` contract (`HEVM_TARGETS`).
