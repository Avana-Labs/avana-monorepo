### V4-01 in detail

The seizure calls `unwind(positionKey, take, zeros, LP_VAULT_SWAP)`. For an ERC-20 pool the batch is:

```
DECREASE_LIQUIDITY(tokenId, 0, 0, 0)
TAKE_PAIR(currency0, currency1, depositor)   <- reverts if a token refuses the depositor
DECREASE_LIQUIDITY(tokenId, take·10^k, 0, 0)
TAKE_PAIR(currency0, currency1, LPVaultSwap)
```

`PoolManager.take` calls the token's `transfer`, and a failed transfer reverts the `unlock` and so the whole `liquidate`. `_take` skips a zero amount, so the lockout needs a non-zero fee in the refusing token; one swap through the range is enough, and a failed seizure leaves the fee in place. The fee belongs to the depositor, so sending it elsewhere needs a delivery path that cannot revert the liquidation, which is what the PayoutEscrow already provides for the borrower surplus.

## Checked and holding

- Slot maths against v4-core `e50237c`: `POOLS_SLOT = 6`, offsets 1 (fee growth global), 3 (liquidity), 4 (ticks), 6 (positions); `slot0` packing with the tick sign-extended from bits 160–183; the tick key `keccak256(abi.encode(int256(tick), ticksSlot))` and fee growth outside at words 1–2; the position key `abi.encodePacked(owner, tickLower, tickUpper, salt)` (58 bytes, as `Position.calculatePositionKey`); `Lock.IS_UNLOCKED_SLOT`. `PositionInfo` decoding (ticks at bits 8 and 32, subscriber in the low byte, 25-byte pool-id prefix in the Lens) matches v4-periphery.
- Fee growth: `feeGrowthInside` follows `Pool.getFeeGrowthInside` branch for branch, unchecked; `feesOwed` equals `Position.update`'s credit, so `_collectAll`'s return equals what `TAKE_PAIR` delivers. A wrapped accumulator cannot panic.
- Removal amounts: `ClPriceMath.amountsForLiquidity` equals `SqrtPriceMath.getAmount0Delta`/`getAmount1Delta` with `roundUp = false` in every branch (see S6), the zero decrease does not move `slot0`, and the PositionManager re-checks the same minimums on `liquidityDelta − feesAccrued`.
- Action encoding: action bytes and `OPEN_DELTA`, `CONTRACT_BALANCE`, `ADDRESS_THIS` equal v4-periphery `Actions` and `ActionConstants`; every params tuple matches `CalldataDecoder`; the batch capacities (10 and 5) cover the native path; fees go to the depositor before the principal to the recipient.
- Native ETH: the PoolManager's ETH transfer is accepted by the PositionManager's `receive` (sender is the PoolManager), `WRAP` and `SWEEP` leave nothing in the PositionManager, the LPVault has no `receive` and never receives ETH; an ETH/WETH pool is refused.
- PoolKey binding: `poolId == keccak256(abi.encode(key))`; currency order is enforced by the PoolManager at initialization; positions match only by the hash of their PositionManager key and the exact range; a burned or never-minted token reads as pool 0; later markets of a pool must name the same reference pool, which must be the factory's pool of the two tokens with the same token order (native leg as WETH).
- Hookless pools cannot carry the dynamic-fee flag (v4-core `Hooks.isValidHookAddress`), so `key.fee` is static.
- Subscribers and approvals: `PositionManager.transferFrom` drops any subscriber on the pull, and `_isEncumbered` refuses one before it, so no subscriber code runs in custody; per-token approvals are cleared on transfer; `permit` needs ERC-1271, which the LPVault lacks; the LPVault never approves.
- Unlock guard: pledge, validate, unwind and release revert `PoolLocked` inside an `unlock`; `collectFees`, `returnPosition` and `returnStray` fail closed through the PoolManager's `AlreadyUnlocked` and the PositionManager's `PoolManagerMustBeLocked`.
- Reentrancy: the PositionManager's `isNotLocked` blocks nested batches; every custody call runs under the Lock for Collateralization only; listing excludes hook tokens.
- Stray NFTs: only PositionManager NFTs are accepted; a position minted straight to the LPVault is a stray the timelock can return; a stray can never become a record (`owner == address(this)` refused).
- Zero liquidity: Collateralization never unwinds 0 units, so the zero decrease of the fee step always hits a position with liquidity (no `CannotUpdateEmptyPosition`); `collectFees` skips a position without liquidity.
- Supply bound: with both supplies below 2^127, each principal, each fee and their sum stay inside `int128`; donations cannot raise a position's fee above the donated amount.
- Oracle market parser: every word is range-checked (addresses within 160 bits, fee within 24 bits, ticks and spacing within `int24`, spacing in `[1, 32,767]`, `unitExp ≤ 18`, hooks zero), so the stored `poolId` is the hash of a canonical key; a malformed or short encoding returns false and `initialize` reverts `MarketMismatch`. The reference mean tick is negated when the reference pool orders the tokens the other way, in both the oracle and the LPVault.
