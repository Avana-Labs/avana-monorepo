# 2.5 Position Proxy and Proxy Manager

> **Status:** In review · **Owner:** Avana Labs · **Last reviewed:** 2026-11-11
>
> **Requirement prefix:** `REQ-PROXY-NNN` · **Math prefix:** `SPEC-PROXY-NNN`

## Purpose

**PositionProxy.** One proxy per wallet per (CDP Spoke, market). The proxy is the borrower's Aave V4 account for that market: it holds the supplied vault-token collateral of exactly one collateral reserve (the market's) and the debt of every debt reserve the account borrows on that Spoke, and it calls the Spoke as itself (`onBehalfOf = address(this)`). Every market therefore has its own Aave account and its own health factor, and no market's collateral backs another market's debt. A wallet that uses two markets, on the same Spoke or on two Spokes, has two proxies (`Q-307`).

The proxy is a logic-free immutable contract. It is not an upgrade proxy: it delegates to no other contract and has no implementation slot, initializer or upgrade path, and no account ever moves from one proxy to another. Its bytecode holds four constructor immutables (`ADAPTER`, `WALLET`, `SPOKE`, `MARKET_ID`) and one state-changing function, `execute(target, data)`, which only the chain's AaveAdapter may call. All account logic (exact approvals reset to 0, supply and the enable-and-assert order for collateral, borrow forwarding, repay with refund, withdrawal, balance-delta checks, collateral cleanup) lives in the Adapter and reaches the Spoke and the tokens as calls made through `execute`. The Adapter sits at a fixed address and upgrades through the chain's timelock, so a fix to account logic reaches every proxy at once, and no exit depends on code inside the proxy (`Q-306`).

The proxy is **not** responsible for: deciding who may act on the account or what call to make (the Adapter); price states, pause state, health-factor checks or caps (RiskModule and Adapter, [2.6](06-aave-adapter.md), [2.7](07-risk-module.md)); minting or burning vault tokens (the Adapter, [2.4](04-vault-tokens.md)); backing records and position custody (Collateralization and the market's LPVault, [2.3](03-collateralization.md), [2.2](02-lp-vault.md)); liquidation, which Aave runs against the proxy's account with no call into the proxy (`Q-116`).

**ProxyManager.** The chain's only creator of PositionProxies. One immutable contract per chain: no upgrade proxy, implementation pointer or setter, owner, role or pause. It deploys each proxy with CREATE2 at an address fixed by `(wallet, spoke, marketId)`. Only the AaveAdapter can ask it to deploy, on the wallet's first pledge to that market, and it refuses a wallet the MarketRegistry has frozen (`Q-242`). It keeps no wallet-to-proxy map: the Adapter keeps the binding, and each vault token keeps its own registry of valid proxies (`Q-224`). Because the chain has one Adapter and the binding is part of the CREATE2 salt and the init code, no Hub, Spoke or market can occupy another's proxy address (`Q-307`).

## Inputs

| From | What |
|---|---|
| AaveAdapter | Every `execute(target, data)` call: Spoke `supply`, `setUsingAsCollateral`, `borrow`, `repay`, `withdraw`; vault-token and debt-asset `approve` (to the Spoke) and `transfer` |
| ProxyManager | Constructor arguments `(ADAPTER, wallet, spoke, marketId)` inside the creating CREATE2 call |
| CDP Spoke / Hub | Borrowed debt asset (Hub `draw` to the proxy); withdrawn vault tokens (Hub `remove` to the proxy); account data, debt balances, supplied shares, collateral status, all read by the Adapter and the Lens from the Spoke |

## Outputs

| To | What |
|---|---|
| CDP Spoke | `supply`, `setUsingAsCollateral`, `borrow`, `repay`, `withdraw` for the proxy's own account, made through `execute` |
| Borrow receiver | Exactly the amount of the debt asset drawn by a borrow (the Adapter's `transfer` through `execute`) |
| Repay payer | Any part of a repay that the Spoke did not consume (refund in the same call) |
| AaveAdapter | Withdrawn vault tokens stay in the proxy for the Adapter to burn in the same call (`Q-224`) |
| Indexers | `ProxyDeployed` (ProxyManager); the Adapter's `UserProxyCreated` keys every proxy to its wallet, Spoke and market |

## Storage

### PositionProxy constructor immutables

The proxy has no storage variables. Its four values are constructor immutables in its bytecode.

| Immutable | Type | Description | Set by |
|---|---|---|---|
| `ADAPTER` | `address` | The chain's AaveAdapter (its fixed ERC-1967 proxy address), the only caller of `execute` | Constructor argument from the ProxyManager |
| `WALLET` | `address` | Bound wallet; non-zero | Constructor argument |
| `SPOKE` | `address` | Bound CDP Spoke; non-zero | Constructor argument |
| `MARKET_ID` | `uint256` | Bound market, a MarketRegistry market listed on `SPOKE`; non-zero | Constructor argument |

### ProxyManager constructor immutables

| Immutable | Type | Description | Set by |
|---|---|---|---|
| `ADAPTER` | `address` | The chain's AaveAdapter; only caller of `deployProxy` and the `ADAPTER` of every proxy | Constructor |
| `MARKET_REGISTRY` | `address` | Source of the address freeze read by `deployProxy` | Constructor |
| `PROXY_CREATION_CODE_HASH` | `bytes32` | `keccak256(type(PositionProxy).creationCode)`, recorded in the deployment manifest; every prediction hashes this creation code followed by the constructor arguments (`REQ-PROXY-052`) | Constructor |

## Permissions

| Function | Who may call | How granted / revoked |
|---|---|---|
| Proxy `execute` | Only `ADAPTER`; the bound wallet and every other address get `OnlyAdapter()` | Constructor immutable; never changes |
| ProxyManager `deployProxy` | Only `ADAPTER` | Constructor immutable; a frozen wallet is refused (`REQ-PROXY-099`) |
| Views | Anyone | Not restricted |

Neither contract has an admin, a role, a pause, a freeze or an upgrade path. No guardian and no timelock operation reaches them. The application pause state (per Hub) and the address freeze live in the MarketRegistry, where the Adapter reads the pause state and the ProxyManager reads the freeze for proxy creation only (`Q-227`, `Q-242`, `Q-308`). What a proxy does is decided by the Adapter, whose upgrades run through the chain's timelock at the normal delay ([2.6](06-aave-adapter.md) `REQ-ADAPTER-003`).

## Dependencies

| Dependency | Type (internal / external) | Calls made | Why |
|---|---|---|---|
| CDP Spoke (standard Aave V4 Spoke) | External | Through `execute`: `supply`, `setUsingAsCollateral`, `borrow`, `repay`, `withdraw` | The proxy is the Aave account |
| Vault token and debt assets (ERC-20) | Internal / external | Through `execute`: `approve` (to `SPOKE` only), `transfer` | Supply, borrow forwarding, repay and refund |
| OpenZeppelin `Create2` (v5.1.0) | External library | — | Address prediction and the CREATE2 creation in the ProxyManager, over the same salt and init-code bytes |
| OpenZeppelin `Address` (v5.1.0) | External library | — | `verifyCallResult` in `execute`: returns the callee's data, or re-raises its revert data unchanged |

The proxy calls nothing of its own accord: every call it makes is one `execute` call the Adapter built. It calls no Avana contract, no price contract and no Lock (`REQ-PROXY-010`, `REQ-PROXY-014`, `REQ-PROXY-078`).

## Events

| Event | Emitted when | Fields |
|---|---|---|
| `ProxyDeployed` (ProxyManager) | `deployProxy` creates a proxy, before the Adapter's first collateral supply through it | `address indexed wallet`, `address indexed spoke`, `uint256 indexed marketId`, `address proxy` |

The proxy emits no event of its own. `UserProxyCreated`, `CollateralSupplied`, `Borrowed`, `Repaid`, `CollateralWithdrawn` and `CollateralDisabled` are emitted by the Adapter, which knows the wallet, the payer, the market and the gates ([2.6](06-aave-adapter.md)). Aave's own `Supply`, `SetUsingAsCollateral`, `Borrow`, `Repay` and `Withdraw` events are emitted by the Spoke with `onBehalfOf` = the proxy. Index key for an account is `chainId + Spoke + proxy`; the proxy names its market (`Q-076`).

## Restrictions

### Identity, form and binding

- `REQ-PROXY-001` Each PositionProxy MUST be a plain immutable contract deployed by `ProxyManager.deployProxy(wallet, spoke, marketId)` with CREATE2, `salt = keccak256(abi.encode(wallet, spoke, marketId))` and init code `type(PositionProxy).creationCode ‖ abi.encode(ADAPTER, wallet, spoke, marketId)`. It MUST NOT delegate to another address in any form (no ERC-1967 proxy, no implementation pointer read from another contract, no delegating clone), and MUST contain no `delegatecall`, no `selfdestruct`, no implementation slot, no initializer and no function that changes its code or its binding. There is no per-proxy version and no move of an account between proxies. Why: Aave V4 has no position transfer, so such a move would be a repay, withdrawal and re-borrow, which is new debt refused in exactly the states (pause, freeze, breaker, full `drawCap`) where a proxy bug would force one; and a per-proxy version would require every Adapter version to drive every proxy version forever. A proxy with no logic has no version to fall behind: every change to account logic is an Adapter upgrade that applies to every proxy at once (`Q-306`). (Source: Q-306, Q-307)
- `REQ-PROXY-002` Each proxy MUST hold `ADAPTER`, `WALLET`, `SPOKE` and `MARKET_ID` as constructor immutables and nothing else. The Adapter takes every target it makes the proxy call from the binding or from Aave: the Spoke is `SPOKE`; the collateral reserve is the market's, `reserveId = ISpoke(SPOKE).getReserveId(hub, IHub(hub).getAssetId(vaultToken))` for the market's vault token and its home Hub, derived at call time ([2.6](06-aave-adapter.md) `REQ-ADAPTER-068`); a debt reserve is accepted only from the MarketRegistry's enabled set for the Spoke ([2.8](08-market-registry.md)); the debt asset is `ISpoke(SPOKE).getReserve(debtReserveId).underlying`. A proxy serves exactly one (CDP Spoke, market): Aave V4 tracks health per account per Spoke, so a separate account per market gives each market its own health factor. (Source: Q-223, Q-239, Q-306, Q-307)
- `REQ-PROXY-003` The proxy constructor MUST revert with `ZeroAddress()` if `adapter`, `wallet` or `spoke` is `address(0)` or `marketId == 0`. The ProxyManager is the only deployer the Adapter recognises, so a contract with the same code deployed by anyone else is never a registered proxy (`REQ-PROXY-055`). (Source: Q-306, Q-307)
- `REQ-PROXY-004` The binding MUST be fixed at creation by the CREATE2 call: the salt and the constructor arguments both carry `(wallet, spoke, marketId)` and the init code carries `ADAPTER`, so the address alone fixes the binding. Whoever triggers the creation, the proxy at that address is bound to that wallet, that Spoke and that market, and executes only that Adapter's calls. There is no initialize step that another address could run first. (Source: Q-107, Q-144, Q-306, Q-307)
- `REQ-PROXY-005` `WALLET`, `SPOKE` and `MARKET_ID` MUST never change; no function transfers, renounces, recovers or rebinds them, and the Adapter never re-keys a record, a seizure list, a rescue counter or a borrow nonce to another proxy. A wallet that wants to move its position repays, withdraws and pledges again from the new wallet. A borrower who loses its key can never withdraw its positions; its debt can still be repaid by any payer through the Adapter ([2.6](06-aave-adapter.md) `REQ-PROXY-027`) or closed by liquidation; this is stated to users as a term of use. (Source: Q-107, Q-212, Q-266, Q-306)
- `REQ-PROXY-006` Neither the proxy nor the ProxyManager MAY use `tx.origin` or check whether a caller or a wallet holds code (`extcodesize` or any other EOA-only check); the only code check in either contract is about a callee or a creation address: `execute` refuses a target without code (`REQ-PROXY-007`) and `deployProxy` refuses a predicted address that already holds code (`REQ-PROXY-051`). The Adapter keys the account on `msg.sender`, so smart-contract wallets and Safes are valid borrowers, and indexers match Avana events by wallet, Spoke, market and proxy, not by `tx.from`. (Source: Q-075, Q-119)

### Code surface

- `REQ-PROXY-007` The proxy MUST expose exactly one state-changing function, `execute(target, data)`, which reverts with `OnlyAdapter()` unless `msg.sender == ADAPTER`, reverts with `InvalidTarget(target)` if `target` is `address(this)`, `address(0)` or holds no code, performs `target.call{value: 0}(data)`, returns the return data, and propagates a revert with the callee's revert data (`CallFailed(target)` when that data is empty). It MUST expose no `delegatecall`, no `receive` or payable `fallback`, no ERC-721 or ERC-1155 receiver, no ERC-1271 `isValidSignature`, no sweep and no other state-changing function. Why: the proxy is the Aave account, so its only caller can act as the account in full; restricting that caller to the Adapter makes the proxy exactly as trustworthy as the Adapter, and putting no selector rule in the proxy means a later Adapter version never needs different proxy code (`Q-306`). The selector inventory of the deployed bytecode is checked at deployment: `execute` and the four views only. (Source: Q-064, Q-116, Q-306)
- `REQ-PROXY-008` The Adapter MUST NOT make the proxy call `Spoke.liquidationCall`, `setUserPositionManager`, `setUserPositionManagersWithSig`, `renouncePositionManagerRole`, `updateUserRiskPremium` or `updateUserDynamicConfig`, and MUST NOT make it approve or activate any position manager. Every Spoke call the Adapter builds uses `onBehalfOf = proxy`; no position manager is needed, because the proxy is the account itself. The Adapter's call builder uses a fixed selector set per target: on `SPOKE`, `supply`, `setUsingAsCollateral`, `borrow`, `repay`, `withdraw`; on the vault token and the debt asset, `approve(SPOKE, x)` and `transfer`. (Source: Q-064, Q-116, Q-145, Q-306)
- `REQ-PROXY-009` The Adapter MUST make the proxy borrow only a debt reserve in the MarketRegistry's enabled set for `SPOKE` ([2.6](06-aave-adapter.md) `REQ-ADAPTER-067`). On a standard Aave V4 Spoke the vault-token reserve is made non-borrowable by the listing payload, and the RiskModule's drift check trips the Spoke's configuration breaker if it ever becomes borrowable ([2.7](07-risk-module.md) `REQ-RISK-074`), so no new debt is drawn against a Spoke whose vault-token reserve can be borrowed. (Source: Q-233, Q-237, Q-309)
- `REQ-PROXY-010` The Adapter MUST make the proxy call only `SPOKE`, the market's vault token and the debt asset of a reserve it is borrowing or repaying. The proxy itself calls no Avana contract and no price contract, so a faulty LPOracle, RiskModule, MarketRegistry or ParameterStore cannot reach it, and it never takes the Lock: it runs only inside an Adapter call that already holds the Lock ([2.16](16-lock.md)). (Source: Q-223, Q-229, Q-306)
- `REQ-PROXY-011` The proxy MUST NOT read any state: no pause state, price state, parameter, cap or health factor. The Adapter applies the call bounds and the RiskModule's pre- and post-checks around every proxy call that adds risk ([2.6](06-aave-adapter.md), [2.7](07-risk-module.md)), so the proxy cannot block a repay or a debt-free withdrawal that the Adapter lets through. (Source: Q-223, Q-227, Q-229, Q-306)
- `REQ-PROXY-012` Errors from the Spoke, the Hub and the tokens MUST propagate unchanged through `execute`; the proxy's own errors are `OnlyAdapter`, `InvalidTarget` and `CallFailed`. The Adapter's errors for the account steps (`ZeroAmount`, `UnitsMismatch`, `BalanceDeltaMismatch`, `CollateralNotEnabled`) are listed below and in [2.6](06-aave-adapter.md), and `packages/protocol` ships the upstream error ABIs so the app can decode them. (Source: Q-119, Q-209, Q-306)
- `REQ-PROXY-013` Every amount the Adapter forwards, refunds or verifies through the proxy MUST be measured as a balance delta of the proxy within the call (`balanceOf(proxy)` after minus before), never as an absolute balance. Tokens donated to the proxy MUST NOT block or change any flow; no path sizes a transfer from `balanceOf(proxy)`. Checked by: HYP-52. (Source: Q-124)
- `REQ-PROXY-014` The proxy MUST NOT call `Lock.acquire` or `Lock.release`: it is not a Lock member. `execute` is callable only by the Adapter, and every Adapter entry point that calls it holds the Lock for the whole call, so no external call made through the proxy (Spoke, Hub, token) can re-enter Avana accounting. (Source: Q-148, Q-223)
- `REQ-PROXY-078` The proxy MUST make no call to any LPOracle, including `poke()`. The first observation of a feed disagreement or failure before a borrow or a withdraw-with-debt is stored by the RiskModule's `preBorrowCheck` and `preWithdrawCheck`, which poke the market's LPOracle before reading its price state ([2.7](07-risk-module.md) `REQ-RISK-056`). (Source: Q-199, Q-229)

### Collateral supply (Adapter steps through `execute`)

- `REQ-PROXY-040` Only the Adapter MUST supply collateral for a proxy, in the same pledge or re-credit call that minted the units to the proxy, holding the Lock ([2.6](06-aave-adapter.md) `REQ-ADAPTER-065`). Any other caller of `execute` reverts with `OnlyAdapter()`. (Source: Q-223, Q-224, Q-306)
- `REQ-PROXY-041` The Adapter MUST revert with `ZeroAmount()` before any proxy call if the units to supply are 0. It derives the reserve from the market's vault token and the Spoke (`REQ-PROXY-002`); a wrong reserve would make the Spoke's `supply` pull a different token, and the balance check of `REQ-PROXY-042` fails with `BalanceDeltaMismatch()`. (Source: Q-223, Q-224)
- `REQ-PROXY-042` The supply step MUST, through `execute`: call `vaultToken.approve(SPOKE, units)`; call `SPOKE.supply(reserveId, units, proxy)`; call `vaultToken.approve(SPOKE, 0)`. The Adapter then MUST revert with `BalanceDeltaMismatch()` unless the proxy's vault-token balance fell by exactly `units` and `vaultToken.allowance(proxy, SPOKE) == 0`, so the proxy holds no vault tokens and no allowance between transactions. (Source: Q-124, Q-224)
- `REQ-PROXY-043` If `SPOKE.getUserReserveStatus(reserveId, proxy)` reports collateral disabled after the supply, the Adapter MUST call `SPOKE.setUsingAsCollateral(reserveId, true, proxy)` through `execute`; afterwards it MUST revert with `CollateralNotEnabled(reserveId)` unless the status reports enabled. Mint, supply, enable and assert run in one call, so the account never holds supplied vault tokens that do not count as collateral. (Source: Q-076, Q-119, Q-224)
- `REQ-PROXY-044` A proxy MUST hold at most one collateral reserve: its market's vault-token reserve on `SPOKE`. The Adapter supplies only that reserve, so the account has 1 collateral reserve and one borrow reserve per debt reserve it borrows. The Spoke's per-account limit is its constructor immutable `MAX_USER_RESERVES_LIMIT`, and Aave V4 applies it to the two counts separately, not to their sum: enabling a new collateral reserve requires the account's collateral count to be below the limit, and the first borrow of a new reserve requires its borrow count to be below the limit (no check at all when the limit is `type(uint16).max`). Any limit of at least 1 therefore admits the proxy's single collateral reserve, and the debt reserves a proxy can borrow are capped at `MAX_USER_RESERVES_LIMIT` whatever its collateral; a first borrow of one more reserve reverts in the Spoke with `MaximumUserReservesExceeded`. Example: with a limit of 2, a proxy holding its vault-token collateral can borrow GHO and USDC, and a first WETH borrow reverts. (Source: Q-193, Q-234, Q-307)
- `REQ-PROXY-045` The supply step MUST NOT check the health factor, a price state, the pause state or Hub shares == assets; pledge eligibility, caps and state gates are applied by the Adapter, Collateralization and the RiskModule before it, and top-ups of indebted accounts continue while Hub shares ≠ assets. (Source: Q-103, Q-132, Q-144, Q-224, Q-229)
- `REQ-PROXY-046` Collateral cleanup: when the proxy's supplied shares of its market reserve are 0, the reserve is not paused (`SPOKE.getReserveConfig(reserveId).paused == false`) and the account has no debt (`SPOKE.getUserAccountData(proxy).borrowCount == 0`), the Adapter MUST call `SPOKE.setUsingAsCollateral(reserveId, false, proxy)` through `execute` and emit `CollateralDisabled(proxy, reserveId)`. Cleanup runs at the end of every withdrawal and partial removal. Restricting it to a debt-free account means the disable never triggers an Aave health-factor validation that could fail; a reserve emptied while debt remains (by a liquidation) stays enabled with a zero balance until the account is debt-free, which changes no health factor. A re-pledge does a fresh enable and refreshes the reserve's dynamic configuration key. (Source: Q-119, Q-193, Q-234, Q-306)
- `REQ-PROXY-047` After a supply step the Adapter MUST emit `CollateralSupplied(proxy, marketId, units, shares)` with the supplied shares the Spoke reports. (Source: Q-076)

### Borrow, repay and withdrawal (Adapter steps through `execute`)

- `REQ-PROXY-087` The borrow step MUST read `asset = SPOKE.getReserve(debtReserveId).underlying`, call `SPOKE.borrow(debtReserveId, amount, proxy)` through `execute`, measure `drawn` as the proxy's `asset` balance delta across that call, revert with `BalanceDeltaMismatch()` unless `drawn == amount` (`SPEC-PROXY-004`), call `asset.transfer(receiver, drawn)` through `execute` (checking the return value as `SafeERC20` does), and verify the proxy's `asset` balance at the end equals its value at the start. The debt asset goes Hub → proxy → receiver in one call and nothing stays in the proxy; every enabled debt asset follows the same path. The receiver rule, the nonce, the deadline and every gate are the Adapter's ([2.6](06-aave-adapter.md)). (Source: Q-064, Q-124, Q-223, Q-233)
- `REQ-PROXY-088` The repay step runs only with `amount > 0` equal to the amount the Adapter measured arriving at the proxy from the payer (`Q-271`); the payer is the repaying wallet in a repay and LPVaultSwap in `deleverageRepay`. Through `execute` the Adapter MUST call `asset.approve(SPOKE, amount)`, `SPOKE.repay(debtReserveId, amount, proxy)` and `asset.approve(SPOKE, 0)`, measure `spent` as the proxy's balance decrease across `SPOKE.repay`, call `asset.transfer(payer, amount − spent)` only when non-zero, and verify the proxy's balance at the end is its balance at the start minus `amount` (`BalanceDeltaMismatch()` otherwise). The repay runs on the proxy's own account because Spoke `repay` accepts only the position owner or its position manager, and the proxy has none. A zero refund is skipped, not attempted, because some ERC-20 tokens revert on zero-amount transfers. (Source: Q-124, Q-212, Q-217, Q-223, Q-255, Q-271)
- `REQ-PROXY-089` The withdrawal step MUST revert with `ZeroAmount()` if `units == 0`, call `SPOKE.withdraw(reserveId, units, proxy)` through `execute`, and revert with `UnitsMismatch()` unless the decoded returned amount equals `units` and the proxy's vault-token balance rose by exactly `units` (`SPEC-PROXY-005`). The withdrawn vault tokens stay in the proxy, and the Adapter burns exactly `units` from it in the same call ([2.6](06-aave-adapter.md) `REQ-PROXY-037`, `REQ-ADAPTER-078`, `REQ-ADAPTER-081`). It then runs the collateral cleanup of `REQ-PROXY-046`. The Adapter never relies on Aave's "amount above balance withdraws everything" behaviour. (Source: Q-066, Q-124, Q-224, Q-254, Q-255)
- `REQ-PROXY-090` The proxy MUST expose the views `ADAPTER()`, `WALLET()`, `SPOKE()` and `MARKET_ID()`. Debt and collateral are read from the Spoke, not from the proxy: `totalDebt(proxy, r) = SPOKE.getUserTotalDebt(r, proxy)` (drawn plus premium accrued to `block.timestamp`, in the asset's own decimals) and `suppliedShares(proxy) = SPOKE.getUserSuppliedShares(reserveId, proxy)`. The Adapter reads them to size repay and check supply and withdrawal, and decides debt-free versus with-debt from `SPOKE.getUserAccountData(proxy).borrowCount` ([2.6](06-aave-adapter.md) `REQ-PROXY-034`); the Lens reads the same values. (Source: Q-076, Q-223, Q-234, Q-260, Q-306)

### ProxyManager

- `REQ-PROXY-050` The ProxyManager MUST be an immutable contract with no upgrade proxy, owner, role, pause or setter, deployed once per chain. Its two address immutables and its creation-code hash never change, so every predicted proxy address on the chain stays equal to the deployed one for the chain's lifetime. A replacement ProxyManager would be a new deployer with different addresses; it is never needed, because the ProxyManager holds no logic beyond deployment and prediction. (Source: Q-226, Q-306)
- `REQ-PROXY-051` `deployProxy(wallet, spoke, marketId)` MUST revert with `OnlyAdapter()` unless `msg.sender == ADAPTER`, with `ZeroAddress()` if `wallet` or `spoke` is `address(0)` or `marketId == 0`, and with `ProxyExists(wallet, spoke, marketId)` if `predictProxy(wallet, spoke, marketId)` already holds code. The Adapter calls it only on the wallet's first pledge to that market, after checking that `marketId` is listed on `spoke` ([2.6](06-aave-adapter.md) `REQ-ADAPTER-066`), so a proxy exists only for a wallet that has pledged to that market. (Source: Q-144, Q-224, Q-307)
- `REQ-PROXY-052` `deployProxy` MUST create the proxy with CREATE2 from the salt `keccak256(abi.encode(wallet, spoke, marketId))` and the init code `type(PositionProxy).creationCode ‖ abi.encode(ADAPTER, wallet, spoke, marketId)` (the creation `new PositionProxy{salt: …}(ADAPTER, wallet, spoke, marketId)` performs), building the salt and the init code once and using the same bytes for the prediction and the creation, revert with `ProxyAddressMismatch(deployed, predicted)` unless the result equals `predictProxy(wallet, spoke, marketId)` (unreachable under the EVM's CREATE2 rule, which hashes the same deployer, salt and init code; the check fails closed if a compiler or chain ever broke it), emit `ProxyDeployed(wallet, spoke, marketId, proxy)` and return the address. `predictProxy(wallet, spoke, marketId) = Create2.computeAddress(keccak256(abi.encode(wallet, spoke, marketId)), keccak256(abi.encodePacked(type(PositionProxy).creationCode, abi.encode(ADAPTER, wallet, spoke, marketId))))`. The init code carries the Adapter and the triple, so the predicted address is exact before creation and the app and the indexer can show an account before it exists. The deployment manifest records `PROXY_CREATION_CODE_HASH`, and the deployment check recomputes `predictProxy` for a test triple and compares it with a deployed proxy. (Source: Q-119, Q-144, Q-307)
- `REQ-PROXY-053` One `(wallet, spoke, marketId)` triple MUST map to at most one proxy and one proxy to exactly one triple: the CREATE2 address is a function of the triple, `ProxyExists` stops a second deployment, and no function rebinds a proxy. The Adapter stores `proxyOf[wallet][marketId]`, `walletOf[proxy]` and `accountOf[proxy]` once, in the call that deployed the proxy, and never overwrites or deletes them; a market belongs to exactly one Spoke, so `marketId` alone names the Spoke. Checked by: QNT-08. (Source: Q-107, Q-307)
- `REQ-PROXY-054` The ProxyManager MUST NOT write any registry of proxies. A proxy becomes a valid vault-token holder only when the Adapter calls `vaultToken.addValidProxy(proxy)` on its first pledge into that market ([2.4](04-vault-tokens.md)), and the Adapter registers only addresses the ProxyManager deployed for `(msg.sender, spoke, marketId)`. (Source: Q-224, Q-307)
- `REQ-PROXY-055` Proxy recognition MUST use the Adapter's binding (`walletOf(proxy) != address(0)`) or a vault token's `isValidProxy(proxy)`; the ProxyManager exposes no `isProxy` view. A CREATE2 address that holds no code yet is not a proxy for any check, and a deployment at a victim's predicted address by anyone other than the ProxyManager is impossible (the CREATE2 deployer is part of the address). Because the chain has one Adapter and the triple is in the salt, a faulty listing on one Hub cannot occupy the proxy address of another Hub's market (AMMN-FLOW-18). Collision assumption: `deployProxy` treats "no code at the predicted address" as a fresh account, so a proxy would inherit any state placed at its address beforehand (ERC-20 allowances, an Aave position-manager approval, collateral or debt on its Spoke account). Reaching such an address needs a collision between an address the attacker controls (an EOA key or a CREATE2 address it can deploy and self-destruct in one transaction) and the predicted address of a triple whose wallet the attacker also chooses, a birthday search of about `2^80` hash evaluations; Avana assumes this infeasible, as for any 160-bit address. The attack only affects the attacker's own proxy, and the AaveAdapter's first pledge into a proxy MUST require that the proxy's Spoke account holds no collateral and no debt on any reserve ([2.6](06-aave-adapter.md)), so an account with inherited positions never takes Avana collateral; an inherited allowance or position-manager approval can only move what the proxy holds, which a fresh proxy's account is required to be empty of. A predicted address with a nonce or storage but no code makes CREATE2 fail with OpenZeppelin's `FailedDeployment()` (`REQ-PROXY-097`). (Source: Q-224, Q-307)
- `REQ-PROXY-056` `ProxyDeployed` MUST be emitted before the Adapter's first supply through the new proxy, and the Adapter emits `UserProxyCreated(wallet, spoke, marketId, proxy)` in the same call, so indexers attribute every Spoke event of that proxy to its wallet, Spoke and market. The indexer attributes Spoke events only to proxies announced by the verified Adapter's `UserProxyCreated`. (Source: Q-076, Q-119, Q-307)
- `REQ-PROXY-085` The ProxyManager constructor MUST take `adapter` and `marketRegistry`, revert with `ZeroAddress()` if either is zero, and store `PROXY_CREATION_CODE_HASH = keccak256(type(PositionProxy).creationCode)`. `adapter` is the Adapter's CREATE3-predicted fixed proxy address, so the ProxyManager and the Adapter can be deployed in either order; the deployment check verifies both immutables and the hash against the manifest. No address holds any power over it after deployment. (Source: Q-226, Q-242, Q-306)
- `REQ-PROXY-086` There MUST be no function on any contract that replaces, upgrades or re-points the code of a deployed PositionProxy. A change to account logic ships as an AaveAdapter upgrade at the normal timelock delay with independent cancellers ([2.6](06-aave-adapter.md) `REQ-ADAPTER-003`), and takes effect for every proxy at once. Blast radius of the proxy code itself is nil beyond the Adapter's: the proxy runs whatever the Adapter sends, so a faulty or hostile Adapter can move whatever the proxies hold or owe through the Spoke up to each `drawCap` ([2.6](06-aave-adapter.md) `REQ-ADAPTER-040`); it cannot send a position anywhere (positions never sit in a proxy), change a Spoke setting or raise an Aave cap. Bound: the normal timelock delay with independent cancellers, and exits that never read the pause state. (Source: Q-223, Q-228, Q-306)
- `REQ-PROXY-099` `deployProxy(wallet, spoke, marketId)` MUST revert with `AddressIsFrozen(wallet)` if `MARKET_REGISTRY.isFrozenAddress(wallet)` is true, after the checks of `REQ-PROXY-051` and before deploying. A frozen wallet has no account to protect in that market, so refusing the proxy only refuses new exposure; a frozen wallet that already has a proxy keeps every exit and rescue top-up ([2.6](06-aave-adapter.md) `REQ-ADAPTER-082`). The ProxyManager reads nothing else from the MarketRegistry, and `predictProxy` reads nothing from it. Checked by: TEST-229. (Source: Q-242)
- `REQ-PROXY-100` Each wallet MUST have one PositionProxy per (CDP Spoke, market) and never more than one. Account isolation: each market has its own Aave account and health factor, so a stale oracle or a depeg in one market can make only that market's account liquidatable, never a healthy position in another market of the same wallet; in the topology simulation, accounts that held several markets in one account were wrongly liquidated through a healthy market, and per-market accounts were not. The cost is one proxy deployment per (wallet, market) on the first pledge and one borrow per market for a borrower who wants debt against two markets. (Source: Q-276, Q-307)
- `REQ-PROXY-101` Neither the PositionProxy nor the ProxyManager MAY hold or grant any role: neither inherits `AccessControl` or `Ownable`, and the deployment check asserts that neither bytecode contains `grantRole`, `transferOwnership` or `upgradeToAndCall`. The only power over a proxy is the Adapter's, and the only power over the Adapter is the chain's timelock ([2.6](06-aave-adapter.md) `REQ-ADAPTER-084`). Checked by: TEST-242. (Source: Q-259, Q-306)

## Math

- `SPEC-PROXY-005` **Collateral unit movement.** Supply: `balanceOf(proxy)` of the vault token falls by exactly `units` across `SPOKE.supply`, and the Spoke reports `units` assets supplied. Withdraw: the Spoke returns exactly `units` and `balanceOf(proxy)` rises by exactly `units` across `SPOKE.withdraw`; the Adapter then burns `units` from the proxy, so the proxy's balance at the end of the call equals its balance before the withdrawal. Units: vault-token base units, one unit per credited unit of the market's position as the market's AMM integration defines it (for Uniswap v3 and Slipstream, one unit of `liquidity` of the exact range; [2.4](04-vault-tokens.md)). Rounding: none in the proxy or the Adapter; with Hub shares == assets every Hub conversion is exact, and the Adapter compares assets, not shares, so a shares ≠ assets state never makes a top-up fail. Overflow: a credited mint is at most `MAX_CREDITED_UNITS < 2^120` ([2.3](03-collateralization.md)), far inside `uint256`. **Why:** every vault token in circulation must stay backed by exactly one credited unit; an inexact supply or withdrawal would leave units outside a record (unbacked) or let Collateralization release a position against fewer units than it credited. **Example:** a record credits `units = 4,815,162,342`. On pledge the Adapter mints 4,815,162,342 to the proxy, the proxy's balance falls from 4,815,162,342 to 0 across `supply` and Aave reports 4,815,162,342 assets supplied. On withdrawal Aave returns 4,815,162,342, the balance rises from 0 to 4,815,162,342, the Adapter burns 4,815,162,342 from the proxy and the balance returns to 0; had Aave returned 4,815,162,341, the withdrawal would revert with `UnitsMismatch()` and nothing would change. Checked by: MATH-AR-26, HYP-05, HYP-44, QNT-07. (Source: Q-066, Q-103, Q-124, Q-224)

## Invariants preserved

The proxy and the ProxyManager must preserve, in words (definitions and IDs in [4.1 Global Invariants](../04-security/01-global-invariants.md)): only the Adapter can make a proxy act; each proxy's binding to its wallet, Spoke and market never changes and its address is the CREATE2 address of that triple; each proxy holds at most one collateral reserve, its market's; Avana's flows leave no vault tokens, debt asset or allowances in the proxy between transactions (every approval is exact and reset to 0 in the same call; a token anyone sends to the proxy directly stays there for good, since there is no sweep, `REQ-PROXY-013`, and changes no flow); supplied units of the market are at most the credited units of the proxy's records, and a shortfall from an unsettled seizure is reconciled by Collateralization on the next withdrawal or seizure settlement (`Q-201`); the proxy's code never changes.
