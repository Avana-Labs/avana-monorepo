# 5.1 Test Requirements

> **Status:** In review · **Owner:** Avana Labs · **Last reviewed:** 2026-11-12

Avana's Foundry tests live under `contracts/test/` (`unit/`, `fuzz/`, `integration/`, `invariant/`, `fork/`, `hostile/`); tests of off-chain components live in the service that owns the code (`web/`, the Convex backend in `services/convex/`, the Ponder indexer, the keeper, `packages/protocol/`). The traceability matrix ([traceability.md](traceability.md)) records which requirements each test links. Formal proofs are in [5.2](02-formal-properties.md); the findings these tests close are in [5.3](03-audit-findings.md).

Columns:

- **Type**: `environment` (harness rule that other tests rely on), `unit`, `fuzz`, `differential`, `boundary`, `access-control`, `invariant` (Foundry invariant test, runs after every handler call), `fork` (Avana-deployed Aave V4 on Anvil or Sepolia, or an Ethereum or Base fork), `hostile` (fork test with a hostile implementation installed through the real AvanaTimelock path at its normal delay), `gas`, `deployment-check`, `keeper`, `off-chain`, `static-analysis` (a security tool over the source or bytecode, section K), `formal` (symbolic execution run as a CI gate, section K).
- **Spec-stage counterpart**: the `MATH-`, `SYM-`, `QNT-`, `HYP-` or `SIM-` checks the test re-proves on real code. A Foundry test reproduces their counterexamples as regression cases. `None` means no spec-stage model covers that behaviour; the test is its only check.
- **Covers**: the decisions (`Q-…`) the test proves. Each test file also lists the `REQ-…` and `SPEC-…` IDs it proves in its tag.
- In code each test carries a `TEST-NNN verifies: <IDs>` comment, which [`trace.py`](trace.py) reads (`Q-173`).
- Global invariants (`INV-…`) are defined only in [4.1 Global Invariants](../04-security/01-global-invariants.md). Section D maps each invariant test to them.
- Fixture values used in examples: GHO debt reserve (18 decimals, Aave fixed price source $1), USDC debt reserve (6 decimals, Chainlink USDC/USD through the AaveOracle), WETH debt reserve (18 decimals); `minPledgeUsd` $10 (`10e8`); `hardHealthFloor` 0 (off, the default) on every market, with a second fixture market at 1.10 for the hard-floor tests; the Lens's `recommendedHealthFactor` 1.10; `keeperFloor` 1 and `MAX_KEEPERS` 32 per chain; normal delay 432,000 s (launch; `MIN_NORMAL_DELAY` 345,600 s), short delay 43,200 s, `GRACE_PERIOD` 1,209,600 s; `ε = floorRoundingAllowance(spoke, r)` = 1 USDC (10⁶ base units; 10¹⁸ for GHO) ([1.5 Parameters](../01-architecture/05-parameters.md)).
- Chain profiles: Ethereum (12 s blocks, Uniswap v3 markets, no sequencer feed) and Base (2 s blocks, Aerodrome Slipstream markets, sequencer-uptime feed and grace period); each profile carries its own feeds, gas price, liquidation gas model, Timelock, Safe and Guardian set, and no minimum debt (`TEST-003`, `Q-381`).
- Liquidation and settlement tests run once for each debt reserve of the fixture. Every settlement amount (caller funding `Kf`, recovery `R`, floor `minRec`, shortfall top-up, Avana fee `A`, keeper reward `kr`, borrower surplus `B` and `keeperOut`) is in the debt asset of the reserve repaid; an example names its asset, and GHO moves only when the repaid debt is GHO (`Q-362`).

## K. Security tooling

Two tiers, each building into its own directory under `contracts/out-security/` and running every tool on everything that exists under `src/` and every property harness under `test/`, found through the build.
